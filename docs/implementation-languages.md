# 実装言語とデプロイ対応方針

## 目的

本プロジェクトは、同じBotの仕様を複数のプログラミング言語で実装し、各言語の実行環境へデプロイできるようにする。

対応言語ごとに仕様を変えるのではなく、共通仕様・共通API・共通テストを基準にする。これにより、どの言語版でも保存処理、返信内容、状態遷移が同じになることを保証する。

なお、ここでいう実装言語と投稿本文の言語は別の概念である。Python版・LINEを基準実装とし、資料に掲載された17プラットフォームを共通イベント契約で扱う。投稿本文の言語判定や翻訳は実装対象外とする。

## 対応プログラミング言語

### Python

- 現行の基準実装とする
- FlaskなどのWebフレームワークでWebhookを提供する
- SQLiteなどの軽量なデータベースを利用できる
- テストとLean 4の仕様モデルを最初に対応させる

### PHP

- 一般的なレンタルサーバーやPHP対応ホスティングへデプロイできる
- Laravelなどのフレームワークを利用できる
- 小規模なWebhookサーバーを低コストで運用しやすい
- Python版と同じOpenAPI仕様およびデータ項目を実装する

### TypeScript / Node.js

- Webhook、外部API連携、非同期処理に適している
- ExpressまたはFastifyを利用できる
- Docker、Vercel、Cloud Runなどへデプロイできる
- JavaScriptではなくTypeScriptを正式な実装言語とする

### Go

- コンパイル済みの単一バイナリとして配布できる
- メモリ使用量を抑えた常駐サーバーを構築しやすい
- DockerやCloud Runなどへのデプロイに適している
- Python、PHP、TypeScript版の仕様が安定した後に追加する

## 対応優先順位

1. Python
2. PHP
3. TypeScript / Node.js
4. Go

Pythonは既存コードを基準実装として完成させる。次に、導入先の多いPHPと、Webhook・API開発に適したTypeScriptを対応する。Goは運用規模や性能要件が明確になった段階で追加する。

Rust、Java、C#などは、現時点では正式対応の対象にしない。必要になった場合も、共通仕様とテストを満たす追加実装として検討する。

## 共通化するもの

各言語で次の内容を共通化する。

- `docs/core-spec.md` に定義された本体仕様
- `docs/lean4-spec.md` に定義された固定フロー
- `docs/openapi.yaml` に定義されたHTTPインターフェース
- データベースのテーブル構成と主要なデータ項目
- Webhookの入力形式と返信形式
- Push通知を行わないこと
- 各言語版で実行する共通テストケース

実装言語固有のフレームワーク、設定ファイル、ログ出力、デプロイ方法は各言語版で異なってよい。ただし、外部から見える動作は共通仕様に一致させる。

## 仕様と実装の関係

```text
Lean 4
  ↓ 固定フローの検証
OpenAPI / JSON Schema
  ↓ 共通インターフェース
Python / PHP / TypeScript / Go
  ↓ 言語ごとのWebhook実装
LINE / Telegram / Discord / その他のプラットフォーム
```

Lean 4はBot本体の実装言語ではなく、固定フローの検証専用とする。各言語版は、同じ入力に対してLean 4のモデルと同じ結果を返すことをテストで確認する。

## デプロイ方針

各言語版は、最低限次の方法のいずれかでデプロイできるようにする。

- Dockerコンテナ
- HTTPSに対応したWebhookサーバー
- 環境変数による秘密情報の設定
- SQLiteまたは外部データベースへの接続
- ヘルスチェック用エンドポイント

LINEなどのプラットフォーム固有処理は、共通の本体ロジックからアダプターとして分離する。これにより、言語とプラットフォームの組み合わせを増やしても、本体ロジックの重複を抑えられる。

## 現在の実装範囲

PHP・TypeScript・Goにも、17プラットフォームの共通カタログ、入力検証、保存、同一種類コンテンツの最新返信処理を実装している。サービス固有の認証・Webhook形式は、各言語のHTTPアダプターまたは外部変換エンドポイントで接続する。

## 完了条件

新しい言語版を正式対応とするには、次の条件を満たすこと。

- 共通仕様に対する実装がある
- OpenAPI仕様に準拠したWebhookを提供できる
- 共通テストケースが通過する
- Dockerまたは対象言語の標準的な方法でデプロイできる
- 秘密情報をソースコードに直接記述しない
- 既存のPython版の動作を変更しない
