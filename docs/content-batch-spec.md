# コンテンツ一括返信仕様

調査日：2026年7月26日

基準実装：Python版・LINE。Telegram、Discord、Instagram、WhatsAppなど17プラットフォームは同じ契約のアダプターとして実装する。

## 目的

ユーザーが文章・写真・音声・動画・ファイルを投稿したとき、保存した投稿と同じ種類の直近投稿を、各プラットフォームで可能な限りまとめて返す。

投稿保存・直近投稿の選択は共通処理で行い、実際の送信方法だけをプラットフォームアダプターに任せる。

## 確定仕様

ユーザーがコンテンツを送信したら、説明文ではなく、送信されたコンテンツと同じ種類の最新コンテンツを、送信元プラットフォームの上限まで返す。

```text
コンテンツを受信
  ↓
保存
  ↓
同じプラットフォーム・同じ種類の最新投稿を取得
  ↓
プラットフォームの最大コンテンツ数まで選択
  ↓
そのサービスで最もまとまって見える形式で送信
```

### 取得条件

直近投稿の検索条件は必ず次の3つとする。

```text
platform = 送信元プラットフォーム
content_type = 受信コンテンツと同じ種類
status = published
```

したがって、LINEで写真を送信した場合はLINEの写真だけを返し、Telegramで動画を送信した場合はTelegramの動画だけを返す。他のプラットフォームや異なる種類の投稿は混ぜない。

### 説明テキストと投稿単位

通常の一括返信には説明テキストを含めない。返信はコンテンツからコンテンツへの直接返信とする。文章とファイルURLも、複数投稿を改行で結合せず、送信された投稿単位ごとに1つのLINEメッセージとして返す。

ただし、次の場合はテキストへフォールバックしてよい。

- 対象コンテンツをネイティブ形式で送信できない
- 公開URLやメディアIDが取得できない
- 送信APIが一時的に利用できない

### 最大件数

共通処理は最大10件を候補として取得する。実際の送信件数はプラットフォームの能力表で切り詰める。

| プラットフォーム | 目標最大件数 | 送信形式 |
| --- | ---: | --- |
| LINE | 5件 | 複数メッセージを1回のReply APIで送信 |
| Telegram | 10件 | メディアグループ |
| Discord | 10件を目安 | 1メッセージへの複数添付 |
| Instagram | 10件を目安 | 個別メッセージを順番に送信 |
| WhatsApp | 10件を目安 | 個別メッセージを順番に送信 |

「最大件数」は固定された共通API上限ではなく、各アダプターが宣言する送信可能件数である。仕様変更やサービス側の制限変更に備え、値はアダプター側で管理する。

## 共通仕様

1. 受信した投稿を保存する。
2. 送信元プラットフォームと同じ `content_type` の公開済み投稿を新しい順に取得する。
3. 受信した投稿を含む最新投稿を最大10件まで候補にする。
4. アダプターの最大件数に切り詰める。
5. 可能なら1つのグループ・メッセージ・返信リクエストへまとめる。
6. まとめられない場合は、複数の送信として順番を維持する。
7. 同じ形式で送れない場合は、公開URLを含むテキストへフォールバックする。
8. 投稿者名・プラットフォームのユーザーIDは返信に含めない。

共通処理が返す値は「同じ種類の返信項目の配列」であり、「1回のAPIリクエストにまとめるか」は共通処理では決めない。

```text
InboundEvent
  ↓
保存
  ↓
同じ種類の直近投稿を取得
  ↓
OutboundReply(messages=[...])
  ↓
PlatformAdapterが送信形式へ変換
```

## プラットフォーム別の送信仕様

| プラットフォーム | まとめ方 | 直近投稿返信の扱い |
| --- | --- | --- |
| LINE | 1回のReply APIに最大5メッセージ | 最大5項目。画像・動画・音声は同種メッセージ、ファイルはURLテキスト |
| Telegram | `sendMediaGroup`でメディアグループ | 写真・動画などはアルバム化。通常メッセージとして個別送信する場合もある |
| Discord | 1メッセージに複数添付 | 同じ投稿を複数添付にまとめる。本文・Embed・添付の制限を別途適用 |
| Instagram Messaging | 基本は1メディア1送信 | 同種投稿を個別メッセージとして順番に送信 |
| WhatsApp Cloud API | 基本は1メディア1送信 | 同種投稿を個別メッセージとして順番に送信 |

### LINE（現行実装）

Messaging APIの1回の返信リクエストには最大5つのメッセージオブジェクトを指定できる。したがって、説明テキストを1件含める場合、コンテンツは最大4件とする。

現行実装では説明テキストを通常返信に含めない方針のため、LINEのコンテンツ返信は最大5件を目標とする。

### Telegram

Bot APIには複数の写真・動画などをメディアグループとして送る `sendMediaGroup` がある。Telegramでは「同じ投稿を複数の通常メッセージで送る」のではなく、対応する種類をメディアグループへ変換する。

### Discord

Discordは1つのメッセージ作成リクエストに複数ファイルを添付できる。画像などは添付を利用し、必要なら本文に説明を付ける。DiscordのHTTPリクエストサイズ、添付数、Embed数などはアダプターの制限として管理する。

### Instagram Messaging

Instagram Messaging APIはメディア送信に対応するが、LINEのような汎用的な「複数メディアを1つの返信配列にまとめる」方式を共通仕様として前提にしない。複数件は個別送信へ分解する。

### WhatsApp Cloud API

WhatsApp Cloud APIは画像・動画・音声・ドキュメントなどのメディアメッセージに対応するが、共通仕様では1メディア1送信として扱う。複数件は個別リクエストへ分解し、送信順序と失敗した項目を記録する。

## 能力宣言

各アダプターは、送信前に次の能力を宣言する。

```python
PlatformCapabilities(
    platform="line",
    max_reply_items=5,
    supports_media_group=False,
    supports_multiple_attachments=False,
    supported_types=["text", "image", "audio", "video", "file"],
)
```

必要な項目は次の通り。

- `max_reply_items`: 1回の返信・送信単位に入れられる項目数
- `supports_media_group`: アルバム等のネイティブ一括送信に対応するか
- `supports_multiple_attachments`: 1メッセージへの複数添付に対応するか
- `supported_types`: ネイティブ形式で送信できる投稿種別
- `fallback`: 対応できない種別をURLテキスト等へ変換する方法

## 共通処理とアダプターの責務

### 共通処理

- 投稿を保存する
- 同じ `content_type` の直近投稿を取得する
- 最大返信件数を能力表から受け取る
- `OutboundReply`を作る
- 投稿順を新しい順に保つ

### アダプター

- Webhook・Gatewayイベントを`InboundEvent`へ変換する
- メディアを取得またはアップロードする
- `OutboundReply`をサービス固有のAPIへ変換する
- 一括送信、複数添付、個別送信を選択する
- 送信失敗とレート制限を処理する

## 複数受信イベントの扱い

複数コンテンツが同じWebhookリクエストに含まれていても、イベントごとの返信トークンや返信期限はプラットフォームごとに異なる。したがって、複数イベントを無条件に1回へ統合しない。

基本動作は次の通りとする。

```text
イベントを受信
  ↓
投稿を保存
  ↓
同種の直近投稿を取得
  ↓
アダプターの方式で最大件数を返信
```

「数秒分の投稿を待って本当のアルバムを作る」機能は、将来のバッチ・キュー機能として別仕様にする。返信トークンの期限切れや、返信済みイベントの再送を避ける仕組みが必要になる。

## 実装上の結論

共通処理では「同じ属性の直近投稿を最大N件返す」と定義する。Nと送信方式はプラットフォームごとに異なる。

```text
LINE      : 最大5項目の返信配列
Telegram  : メディアグループ
Discord   : 複数添付メッセージ
Instagram : 個別送信
WhatsApp  : 個別送信
```

この方式なら、ユーザーから見た目的は同じまま、各サービスの仕様に合わせて安全に送信できる。

## 現在の実装との差分

この仕様は確定した共通仕様である。Pythonの共通サービス層はプラットフォームとコンテンツ種別で直近投稿を絞り込み、各アダプターがそれぞれの送信上限・送信方式へ変換する。実サービスの送信には各サービスの認証情報が必要である。
