# LINE BOT ミニSNS仕様書

## 1. 概要

登録済みのLINEユーザーが、LINE上からテキストまたは画像を投稿できるミニSNSを提供する。
投稿はデータベースへ保存し、他の登録済みユーザーが確認を要求したタイミングで新着投稿をLINEメッセージとして返す。

本仕様書は初期版（MVP）の仕様を定義する。現在の郵便番号検索機能は、ミニSNS機能へ移行する際に置き換える想定である。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| 登録者 | BOTの利用登録を完了したLINEユーザー |
| 投稿 | 登録者が送信したコンテンツ。テキスト、画像、音声、動画、ファイルなどを含む |
| 閲覧者 | 新着確認によって投稿を取得する登録者 |
| 管理者 | 登録者や投稿を管理する運営者 |

## 3. MVPの目的

- LINEだけで簡単に投稿できる
- 登録者同士で投稿を共有できる
- 登録者が必要なタイミングで他の登録者の投稿を取得できる
- 不正なユーザーや問題のある投稿を管理者が停止・削除できる

## 4. 想定用途

このBOTは、LINEに登録しているメンバー同士で情報を共有する、小規模なコミュニティ向けSNSとして利用する。
コミュニティのテーマはペットに限定せず、運営者が設定して利用できる。

### 利用者の用途

- 登録メンバー全体へのお知らせを投稿する
- イベント、勉強会、サークル活動などの情報を共有する
- 日常の短いメッセージや近況を共有する
- 活動場所や商品の写真などをメンバーに見せる
- LINEアプリを離れずに、コミュニティ内の情報を受け取る

### 具体例：ペットコミュニティ

以下は利用イメージの一例であり、ペット以外のコミュニティでも同じ仕組みを利用できる。

ペットを飼っている人が参加するコミュニティで、次のように利用する。

1. Aさんが「今日の散歩に行きました」というメッセージや、ペットの写真をBOTへ送る。
2. BOTがAさんの投稿を保存する。
3. BさんやCさんが「新着」と送信すると、Aさんのメッセージまたは画像が返される。
4. BさんやCさんが自分のペットの写真を投稿する。
5. Aさんが「新着」と送信すると、BさんやCさんの投稿が返される。

つまり、投稿者と受信者が1対1でやり取りするのではなく、登録者の誰かが投稿した内容を、投稿者以外の登録者全員で共有する仕組みとする。

### その他の利用例

- 学校・クラスの連絡コミュニティ
- 趣味・サークルの情報共有
- 地域コミュニティのお知らせ
- イベント参加者同士の共有スペース
- 社内チームやプロジェクトの簡易掲示板
- 商品、作品、写真などを共有するグループ

運営者は設定ファイルでコミュニティ名や説明文を変更し、目的に応じてテキスト投稿、画像投稿、新着確認などの機能を有効化する。

#### ペットコミュニティでの投稿例

| 投稿者 | 投稿内容 | 配信先 |
| --- | --- | --- |
| Aさん | 「うちの犬が初めて海に行きました」＋画像 | 新着確認したBさん、Cさん |
| Bさん | 「今日の猫の様子」＋画像 | 新着確認したAさん、Cさん |
| Cさん | 「おすすめの動物病院を教えてください」 | 新着確認したAさん、Bさん |

### 運営者の用途

- 登録メンバーが確認した投稿や取得履歴を管理する
- 利用停止や投稿削除によってコミュニティを管理する
- 設定ファイルで必要な機能だけを有効にする
- 利用状況に応じて、返信・リアクション・通報などの機能を段階的に追加する

### 想定しない用途

- 不特定多数へ公開する一般向けSNS
- 個人間の秘密情報や機密情報の送受信
- 医療、金融、法律などの専門的な相談サービス
- 大規模なユーザー数を前提としたリアルタイム配信サービス

## 5. 機能要件

### 5.1 ユーザー登録

- ユーザーがBOTへ初めてメッセージを送った時点で、LINEのユーザーIDを保存する。
- 表示名、登録日時、利用状態を保存する。
- 利用状態は `active`（利用可能）、`blocked`（利用停止）、`deleted`（退会扱い）を持つ。
- 登録済みユーザーが再度メッセージを送った場合は、既存ユーザーとして扱う。
- LINEの友だち解除を検知した場合は、新着投稿の取得対象から外す。

### 5.2 コンテンツ投稿

- 登録者が対応しているコンテンツを送信すると、その内容を投稿として保存する。
- 投稿時には他のユーザーへ自動送信しない。
- 利用できるコンテンツ種別は設定ファイルで有効・無効を切り替えられる。
- 投稿には1つ以上のコンテンツを含められるようにする。複数コンテンツへの対応時期は設定で管理する。
- 投稿者へは受付結果を返信する。
- 空文字、空白だけのテキスト投稿は受け付けない。
- MVPでは投稿の編集は提供しない。

### 5.3 対応コンテンツ

| 種別 | 内容 |
| --- | --- |
| `text` | テキスト本文 |
| `image` | 写真・画像 |
| `audio` | 音声メッセージ・録音 |
| `video` | 動画 |
| `file` | PDFなどのファイル |
| `location` | 位置情報 |
| `sticker` | LINEスタンプ。必要な場合のみ有効化 |

- LINEから受信したメディアは、必要に応じて外部ストレージへ保存する。
- ユーザーが新着確認した時に、対応するLINEメッセージ形式で返す。
- LINEの仕様上そのまま返せない形式は、ダウンロードURLや説明テキストに変換して返す。
- 種別ごとの最大サイズ、対応形式、保存期間を設定ファイルで変更できるようにする。
- 画像、音声、動画、ファイルには任意で説明文を付けられるようにする。

### 5.4 複数コンテンツの組み合わせ

- テキストと画像、音声と説明文など、複数のコンテンツを同一投稿として扱えるようにする。
- 画像受信後の次のテキストを説明文とするか、リッチメニュー等で投稿操作を明示するかは実装時に決定する。
- 最初に対応する種別は設定ファイルで選択する。

### 5.5 投稿の取得（Pull型）

- 投稿時には投稿を保存するだけで、他のユーザーへ自動送信しない。
- ユーザーが `新着`、`タイムライン`、またはリッチメニューを操作した時に、新しい投稿を取得する。
- 取得対象は、最後に確認した時刻以降の投稿とする。
- 投稿者本人の投稿を表示するかどうかは設定で指定できる。初期値は表示する。
- 取得した投稿を、ユーザーへの返信メッセージとして送信する。
- 1回に返す投稿数の上限を設定する。
- 取得済みの投稿を記録し、同じ投稿を何度も返さない。
- 投稿時の全員へのPush配信は、料金を抑えるためMVPでは使用しない。

### 5.6 コマンド

MVPでは以下の文字列をBOTの操作として予約する。

| 入力 | 動作 |
| --- | --- |
| `登録` | 利用登録する |
| `退会` | 利用を停止し、配信対象から外す |
| `使い方` | 操作方法を表示する |
| `キャンセル` | 投稿途中の操作を取り消す |

上記以外のテキストは通常の投稿として扱う。ただし、管理者コマンドは一般ユーザーには公開しない。

### 5.7 管理機能

- 管理者はユーザーを利用停止にできる。
- 管理者は投稿を削除または非公開にできる。
- 管理者は投稿履歴、取得状況、エラーを確認できる。
- 管理者権限はLINEユーザーIDなどの環境変数で指定する。

## 6. 基本操作フロー

### 初回利用

1. ユーザーがBOTへメッセージを送る。
2. BOTがユーザー情報を保存する。
3. BOTが利用方法を返信する。

### テキスト投稿

1. 登録者がテキストを送信する。
2. BOTが投稿内容を検証する。
3. 投稿をデータベースへ保存する。
4. 投稿者へ「投稿しました」と結果を返信する。

### 新着投稿の確認

1. ユーザーが `新着` または `タイムライン` と送信する。
2. BOTがそのユーザーの最終確認時刻を調べる。
3. 最終確認時刻以降の投稿を取得する。
4. テキストまたは画像をLINEの返信メッセージで送る。
5. 取得時刻を更新する。

新着投稿がない場合は、「新しい投稿はありません」と返信する。

### 画像投稿

1. 登録者が画像を送信する。
2. BOTが画像コンテンツを取得する。
3. 画像をストレージへ保存する。
4. 投稿情報をデータベースへ保存する。
5. 投稿者へ受付結果を返信する。

## 7. データ仕様

### users

| 項目 | 内容 |
| --- | --- |
| `id` | 内部ID |
| `line_user_id` | LINEユーザーID（一意） |
| `display_name` | LINE表示名 |
| `status` | `active` / `blocked` / `deleted` |
| `created_at` | 登録日時 |
| `updated_at` | 更新日時 |

### posts

| 項目 | 内容 |
| --- | --- |
| `id` | 投稿ID |
| `user_id` | 投稿者ID |
| `type` | `text` / `image` / `audio` / `video` / `file` / `location` / `sticker` |
| `text` | テキスト本文またはコンテンツの説明文 |
| `media_url` | 保存画像の参照先 |
| `status` | `published` / `hidden` / `deleted` |
| `created_at` | 投稿日時 |

### post_reads

| 項目 | 内容 |
| --- | --- |
| `id` | 取得記録ID |
| `post_id` | 投稿ID |
| `user_id` | 取得したユーザーID |
| `read_at` | 取得日時 |

## 8. 非機能要件

- LINE Webhookの署名検証を必ず行う。
- アクセストークン、チャンネルシークレット、データベース接続情報は環境変数で管理する。
- Webhook処理は短時間で応答する。
- 投稿時の全員へのPush配信を行わず、ユーザーの要求時に返信することで配信料金を抑える。
- 投稿本文と画像URLはログへそのまま出力しない。
- 投稿、ユーザー、取得記録を定期的にバックアップする。
- 画像や投稿の保存期間と削除方法を運用ルールとして定める。

## 9. 受け入れ条件

- 未登録ユーザーが登録できる。
- 登録者のテキスト投稿が保存される。
- 登録者の画像投稿が保存される。
- ユーザーが新着確認を行うと、他の登録者の投稿を取得できる。
- 投稿時には登録者全員へ自動送信されない。
- 一度取得した投稿が、設定に反して何度も表示されない。
- 退会者・停止者が新着投稿を取得できない。
- Webhookの不正リクエストが拒否される。

## 10. 未決事項

- 登録は自動登録にするか、`登録` コマンドを必須にするか
- 投稿への返信、リアクション、削除を提供するか
- 画像の最大サイズ、対応形式、保存期間
- 投稿を時系列で閲覧するWeb画面を作るか
- 1回の新着確認で返す投稿数、画像数、メッセージ分割ルール
- 不適切な投稿の通報機能を設けるか
- LINEのPush API料金・配信上限を踏まえた運用方法

## 11. 設定ファイルによる機能制御

BOTで利用できる機能は、設定ファイルから切り替えられるようにする。
機能追加時も、設定値を追加することで段階的に公開できる構成とする。

### 11.1 設定ファイル例

ファイル名は `config.yaml` または `config.json` とする。形式は初期実装時に決定する。

```yaml
features:
  registration: true
  text_post: true
  image_post: true
  image_caption: false
  post_fetch: true
  post_delete: false
  reactions: false
  replies: false
  report: false
  web_timeline: false

timeline:
  include_author_posts: true
  posts_per_request: 10
  mark_as_read: true

media:
  enabled_types:
    - image
    - audio
    - video
    - file
  max_file_size_mb:
    image: 10
    audio: 20
    video: 50
    file: 20
  allowed_mime_types:
    image:
      - image/jpeg
      - image/png
  retention_days: 30
```

### 11.2 設定項目

| 設定 | 内容 |
| --- | --- |
| `features.registration` | ユーザー登録を許可する |
| `features.text_post` | テキスト投稿を許可する |
| `features.image_post` | 画像投稿を許可する |
| `features.image_caption` | 画像へのキャプションを許可する |
| `features.post_fetch` | ユーザー要求時に新着投稿を取得する |
| `features.post_delete` | 投稿削除機能を有効にする |
| `features.reactions` | リアクション機能を有効にする |
| `features.replies` | 返信機能を有効にする |
| `features.report` | 通報機能を有効にする |
| `features.web_timeline` | Webタイムラインを有効にする |
| `timeline.include_author_posts` | 自分の投稿をタイムラインに含める |
| `timeline.posts_per_request` | 1回の新着確認で返す投稿数 |
| `timeline.mark_as_read` | 取得した投稿を既読として記録する |
| `media.enabled_types` | 有効にするコンテンツ種別 |
| `media.max_file_size_mb` | 種別ごとの最大ファイルサイズ |
| `media.allowed_mime_types` | 種別ごとに許可する形式 |
| `media.retention_days` | メディアの保存期間 |

### 11.3 設定による動作

- 無効な機能が要求された場合、BOTは「現在利用できません」と返信する。
- `text_post` と `image_post` など、すべての投稿種別が無効な場合は投稿機能を停止する。
- 設定で無効にしたコンテンツを受信した場合、BOTは「現在利用できません」と返信する。
- `post_fetch` が `false` の場合、新着投稿の取得機能を停止する。
- `registration` が `false` の場合、新規ユーザー登録は受け付けず、既存の登録者だけを利用対象にする。
- 設定ファイルの読み込みに失敗した場合は、起動を停止して設定ミスを明確に通知する。
- 設定変更の反映方法は、再起動時に読み込む方式を基本とする。
- 秘密情報（アクセストークン、チャンネルシークレット、DB接続情報）は設定ファイルに書かず、環境変数で管理する。

### 11.4 環境変数

`.env.example` を参照して、LINEの認証情報と実行環境のパスを指定する。
画像・音声・動画をLINEへ返すには、`MEDIA_BASE_URL` にLINEからアクセス可能な公開HTTPS URLを設定する。

## 12. 初期実装方針

1. 設定ファイルと環境変数を読み込む。
2. SQLiteへユーザー、投稿、取得記録を保存する。
3. テキスト投稿を実装する。
4. 有効化されたメディアの取得と保存を実装する。
5. 「新着」などの要求に対するPull取得を実装する。
6. 取得記録とエラーハンドリングを追加する。
7. テストとデプロイ環境で受け入れ条件を確認する。
